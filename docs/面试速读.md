# 三项工具语义机制：面试速读

更新：2026-11-03。先记三句话：**同操作换描述仍算重复；测试时间变化不算新证据；后台任务允许有限等待。**

## 项目怎么介绍

这是一个在已有 DeepSeek Harness 循环守卫上做改进的个人项目，采用 AI 辅助开发。先修复真实工具结果事件接入及调用生命周期，再加入工具专属的操作身份、结果证据和等待预算。当前用真实工具运行时和受控夹具完成组件对照，完整模型 Agent 任务评测仍待完成。

## 三项机制各讲一个例子

**1. 操作身份：做的事情没变，描述变了也不能绕过。**

同一个命令、同一个工作目录，仅把“运行测试”改成“再试一次”，实际操作没有变。新规则只忽略 bash/pwsh 中合法的 description，保留 command、workdir、timeoutMs、权限、justification 和未知执行字段；命令中的引号及空白不随意改写。对应 `tool-semantics.js` 的 `actionArguments`。

**2. 结果证据：日志变了，不一定取得进展。**

Python 测试一直因相同断言失败，但每次输出启动时间和耗时。有限的 unittest 适配器解析程序退出状态，只消除明确的测试时间噪声，用剩余证据判断是否新信息。新错误和测试成功仍能提供新证据；返回已经见过的旧错误不反复刷新进展。工具 `isError=false` 只表示工具成功返回，不能等同于 `exitCode=0`。

首次出现的失败可能有诊断价值，因此“提供新证据”与“任务成功”是两回事。每个操作最多记录 64 个新的语义证据，按 session/turn 保存。

**3. 有限等待：允许等，但要知道等多久、查几次。**

后台工作尚未结束，重复查询可能合理。新规则区分 running 与终态，使用独立等待账本；running 不推进 progress epoch，也不占用普通无进展调用计数。账本按 job_id 及 turn 限制查询次数、经过时长与查询频率，普通工具取得进展也不会把等待预算补满。

可选宿主作业注册表通过非消费读取提供最新状态，已结束的作业可在自身等待预算耗尽后收集一次最终结果，仍受本轮总查询上限约束。未提交的取消会释放预留；已开始查询仍计数。

默认限额：每作业 12 次、每轮总计 32 次、每作业 120 秒、查询起点最小间隔 200 毫秒。组件实验为了快速复现使用更短等待窗口和明确的场景预算，不是生产推荐参数。

## 对照实验实际得到了什么

| 场景 | B-safe：只含接入及生命周期修复 | D：三项语义机制 |
|---|---|---|
| 同命令换描述，8 次请求上限 | 8 次均执行 | 执行 2 次，第 3 次拒绝 |
| 实际 Python 失败测试含时间噪声，8 次上限 | 8 次失败均执行 | 执行 2 次，第 3 次拒绝 |
| 约 500ms 后完成的真实后台进程 | 第 3 次查询被拦，进程当时仍在运行 | 本次 6 次查询取得 completed |
| 作业持续运行，允许最多 4 次等待 | 第 3 次因重复提前被拦 | 允许 4 次，第 5 次因等待预算拒绝 |

同时比较原版 A、仅桥接 B、调宽阈值 C。C 也完成正常等待，但继续放行重复失败；因此不能把“正常等待恢复”单独归功于语义策略。3 条消融分别关闭一项机制，对应缺陷随之恢复。

目前 38 条自动回归通过；主实验 6 场景 × 5 组，加 3 条消融，共 33 条组件轨迹。另保留 19 条历史缺陷/控制回放，不合并计算准确率。

完整结果与配置：[组件报告](experiments/semantic-components-2026-11-03.md)。复现：`npm.cmd test`、`npm.cmd run semantics`、`npm.cmd run report:semantics`。

## 面试必须守住的边界

- 真正使用了 Cordis、ToolRuntime、文件、Python 测试和 Node 子进程；模型动作、工具定义和注册表接口是受控夹具，没有完整 Agent 自主任务收益数据。
- 去噪只针对已知 unittest/失败夹具格式，其他时间和数字保留。不是通用日志语义理解器。
- 等待策略沿用严格停止反馈，频率/预算拒绝会限制本轮后续工具；不自动睡眠重试，不强杀后台进程，也未新增完整通知唤醒调度器。
- 框架本来就有进展、重复组和预算。当前新增点是工具专属身份、受控证据和有边界的等待规则；范围与收益由这些用例限定。
- 个人职责如实记录：已参与需求、范围和机制讨论，编码与自动验证由助手辅助，独立操作和代码理解仍需本人验收。

## 三分钟复述顺序

先讲读→写→再读暴露结果接入问题；再讲原参数/原始日志/普通重复规则各自遗漏什么；分别用“改描述”“测试时间噪声”“后台等待”三个例子解释新增规则；最后给出以上成对结果和消融，说明完整模型任务与一般性收益还待验证。
